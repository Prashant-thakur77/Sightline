# S2: Vault with purchase, then reuse without the buyer

## Question

Can a sandbox buyer save PayPal during a first purchase (Orders v2, `payment_source.paypal.attributes.vault`
with `store_in_vault: ON_SUCCESS`, `usage_type: MERCHANT`, `customer_type: CONSUMER`), for both the AUTHORIZE
(pay after check) and CAPTURE intents? Can a second order with `payment_source.paypal.vault_id` then complete
with no approval step?

## What we ran

`packages/db/node_modules/.bin/tsx packages/paypal/spikes/run.ts s2-vault` (add `--headed` if the sandbox blocks headless browsers).

1. AUTHORIZE order with vault attributes, approved headlessly on www.sandbox.paypal.com as the sandbox buyer,
   then authorized; vault id read from the response and the order; authorization voided to clean up.
2. CAPTURE order with vault attributes, approved the same way, then captured; vault id, PayPal customer id,
   payer id and capture id recorded.
3. Payment token read back (`GET /v3/vault/payment-tokens/{id}`) and listed by customer.
4. A second CAPTURE order with only `vault_id` (buyer not present); checked it completes without an approval link.

## Decision

<!-- decision:start -->
Proposed: vault works in sandbox. First purchase saves PayPal with store_in_vault ON_SUCCESS (vault id and customer id recorded); repeat purchases use payment_source.paypal.vault_id and completed without buyer approval. Make vault the default for returning buyers.

## Fallback

Popup checkout every time, still bound to the readback and the payment gate. Report it honestly in the demo.
