# S12: PayPal approval window with screen readers (manual protocol)

## Question

Can a blind buyer complete the PayPal sandbox approval window (login, review, pay, and the save-PayPal consent)
with NVDA and VoiceOver, starting from our checkout button? What works, what breaks, and how bad is it?

## Setup

- Sandbox only. Use the sandbox personal buyer from `.env.local` and an order created by our app (or by
  `spikes/run.ts`) so the window is a real sandbox approval for a known amount and merchant.
- Run each configuration in a clean browser profile, speech on, braille off, default verbosity.

| ID  | Screen reader          | Browser | OS                           |
| --- | ---------------------- | ------- | ---------------------------- |
| A   | NVDA (current release) | Firefox | Windows 11                   |
| B   | NVDA (current release) | Chrome  | Windows 11                   |
| C   | VoiceOver              | Safari  | macOS (current)              |
| D   | VoiceOver              | Safari  | iOS (current), redirect mode |

## Tasks (keyboard or gestures only, no sighted help)

1. From our page, activate the PayPal button. Note whether the popup or redirect is announced and where focus lands.
2. Find and fill the email field, move to the next step, fill the password, log in.
3. If a one-time code or "use password instead" choice appears, record how it is announced and whether it can be reached.
4. On the review page, find and hear: the merchant name, the total, the shipping address, and the payment method.
5. For a vault order, find the consent to save PayPal for future purchases and hear what it says.
6. Activate Pay (or Continue / Agree and continue). Confirm the window closes or redirects back.
7. Back on our page, check focus returns to a sensible place and our announcer says what happened next.
8. Repeat task 1, then cancel from inside the PayPal window. Check that our page announces the cancellation and how to retry.

## What to record per task

- Pass, pass with difficulty, or blocked.
- Time on task (seconds) and the number of extra keystrokes or swipes.
- Exact speech for any unlabeled control, missing heading, focus jump, timeout or error.
- Whether amount and merchant are spoken before the pay button.
- A screenshot and a short audio or screen recording of every blocker (sandbox data only).

## Severity

- Blocker: the task cannot be finished without sighted help.
- Serious: finished, but with guessing or more than 30 seconds of searching.
- Minor: finished; wording or focus order is awkward.

## Decision rule

- Any blocker in tasks 2 to 6 on A or C: make vault reuse the default path so the window is needed once, add a
  spoken pre-briefing of what the window will ask, and offer a helper link for the first approval.
- Serious issues only: keep the popup for first purchases, add pre-briefing, report findings to PayPal.
- Minor only: no change; note the findings.

## Fallback

Report the findings honestly; make vault the default path to minimise popup use (depends on S2).
